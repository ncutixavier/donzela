# Donzela

Cycle-tracking app for women in Rwanda. Kinyarwanda is the default; English and French are included.
Offline first: SQLite on the phone is the source of truth.

## Run

```bash
flutter pub get
dart run build_runner build      # Drift code (re-run after table changes)
flutter gen-l10n                 # ARB → AppLocalizations (runs on build too)
flutter test                     # unit, data and widget tests
flutter run                      # needs an Android device or emulator
flutter build apk --debug
```

## Layout

```
lib/
  core/        theme tokens, router, l10n helpers, shared widgets (ring, month grid, PIN pad)
  data/        Drift database, tables, DAOs, repositories, bundled seed content
  features/    onboarding, today, daily_log, calendar, report, learn, help, settings, lock
  services/    prediction (pure Dart), security (PIN hash), notifications,
               analytics (allowlisted events), sync (queue + CloudStore interface)
  l10n/        app_rw.arb (template), app_en.arb, app_fr.arb
test/          prediction (29), data (8), services (5), widget (flow tests)
```

## Learn content

Articles are Markdown in `assets/content/{rw,en,fr}/{id}.md`, listed in `assets/content/index.json`.
There are 11 topics in 3 languages (33 files). They cover cycle basics and phases, ovulation and fertile days,
irregular cycles, myths, when to see a health worker, food and movement, period pain, period hygiene,
contraception and emergency contraception.

**Review workflow.** Each file has `reviewed_by:` and `reviewed_on:` in its front matter.
- Release builds show only articles with a reviewer.
- Debug builds show every article, labelled as a draft.
- The Kinyarwanda text is a first draft. A native speaker must check it, and a health advisor must check all three languages.

## Rules the code enforces

- Every user-visible string is in the ARB files.
- Screens reach data only through repositories; every write also adds a `sync_queue` row in the same transaction.
- Analytics accepts only allowlisted events and parameters; no dates, symptoms, moods, flow or notes.
- Only reviewed articles are returned to Learn.
- The PIN is stored as a salted SHA-256 hash in secure storage; failed attempts and lockout survive app restarts.
- FLAG_SECURE is set while the PIN is on.

## Firebase (project `donzela`)

- Apps: Android and iOS, both `health.donzela.donzela`. Config files: `android/app/google-services.json`, `ios/Runner/GoogleService-Info.plist`, and `lib/firebase_options.dart` (generated by `flutterfire configure`).
- Android debug SHA-1 and SHA-256 are registered. Add the release key fingerprints before publishing.
- Enabled: Authentication (Google, Anonymous), Cloud Firestore (africa-south1, production mode), Crashlytics, Analytics.
- Security rules: `firestore.rules`, deployed with `firebase deploy --only firestore:rules --project donzela`.
- Google sign-in is used for backup and restore. Anonymous sign-in is enabled in the console but the app does not use it.
- Firebase is optional at runtime. If it cannot start, the app runs offline with backup disabled.

## Configuration (Firebase and environment)

Firebase client settings are not stored in the repository. They come from environment variables:

- **Locally:** copy `.env.example` to `.env` (gitignored), fill in the values from the Firebase console and Google Cloud Console, then run `dart run tool/generate_firebase_config.dart`. This writes `lib/firebase_options.dart`, `android/app/google-services.json` and `ios/Runner/GoogleService-Info.plist`, all gitignored.
- **Without values:** the generator writes placeholders and prints a warning. The app then runs offline, and tests and CI still compile.
- **CI:** the same names are GitHub Actions secrets (repository settings, Secrets and variables, Actions). The workflow in `.github/workflows/ci.yml` writes the files before analysis, tests and the Android build.
- **iOS URL scheme:** `ios/Runner/Info.plist` needs the reversed iOS client ID as a URL scheme. The generator prints the value to use.

Never commit `.env` or the generated files. The Google API key in them is flagged by secret scanning.

## Web deployment

GitHub Actions builds, analyzes and tests the Flutter web app before deploying to Firebase Hosting (`donzela`).

- Open or update a PR from this repository: deploy a unique `pr-<number>` preview and post its URL on the PR. Previews expire after 7 days. Fork PRs build and test without deploying.
- Merge into `staging`: update the `staging` preview channel (expires after 30 days).
- Merge into `main`: deploy the live site at https://donzela.web.app. Pushes to these branches also deploy.
- The Web workflow can also be run manually on `staging` or `main`.

Required repository secret: `FIREBASE_SERVICE_ACCOUNT_DONZELA`, containing a Firebase Hosting deployment service account JSON key. Client configuration uses the `FIREBASE_*` secrets listed above, including `FIREBASE_WEB_APP_ID` and `FIREBASE_WEB_API_KEY`. Deployment jobs check out `firebase.json` and download the exact web artifact that passed the build checks.
